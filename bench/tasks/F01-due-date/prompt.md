Tasks need an optional due date. Users pick it in the task form in a date field labelled "Due date" and see it in the tasks table in a "Due" column; tasks without a due date show "—" there. Store it as `dueDate`, an ISO date string like `2026-12-31` or null, through the whole stack: the contract, the database with a migration, the API and the web app. The API must reject a value that is not a valid date. Existing tasks keep working. Update existing tests where the change requires it.
