Когда планы меняются, люди удаляют бронирования, и потом никто не знает, что встреча вообще была. Бронирования нужно отменять, а не удалять.

Добавь бронированиям `cancelledAt`: null у действующего бронирования, ISO-метка времени, которую ставит сервер при отмене; клиент не может задать её через POST или PATCH. `POST /api/bookings/:bookingId/cancel` отменяет бронирование и возвращает его, отвечает 404 на неизвестный id и 409 с `{ "message": "Booking is already cancelled" }`, если оно уже отменено. Отменённое бронирование остаётся в списке, но больше не занимает переговорную: другое бронирование на ту же переговорную, дату и часы принимается.

В таблице у каждого действующего бронирования появляется кнопка "Cancel" (accessible name "Cancel <title>") с диалогом подтверждения с заголовком "Cancel booking?" и кнопками "Keep" и "Cancel booking". После подтверждения в строке вместо кнопки показывается бейдж "Cancelled", без перезагрузки. Сначала контракт, затем таблица с миграцией, API и страница; добавь тесты с обеих сторон.
