Нам нужна адресная книга. Пользователь открывает "Contacts" из главной навигации и видит по адресу `/contacts` таблицу: имя, email, телефон ("—", если его нет) и группа. Кнопка "New contact" открывает `/contacts/new`, форму с кнопкой "Create", после которой пользователь возвращается к списку.

Поля контакта: "Name" (`name`, обязательное, до 100 символов, сообщение "Name is required"), "Email" (`email`, корректный email, сообщение "Enter a valid email", уникален: повтор даёт 409 с `{ "message": "A contact with this email already exists" }`), "Phone" (`phone`, необязательное: плюс и от 7 до 15 цифр, сообщение "Use the format +123456789", null если пусто), "Group" (`group`, селект с вариантами Family, Friends и Work, хранится как `family`, `friends`, `work`, по умолчанию Friends) и `favorite`, булево поле, которого нет в форме: новые контакты не избранные.

Избранное: в каждой строке есть кнопка-переключатель с accessible name "Add <name> to favourites" или "Remove <name> from favourites"; она обновляет контакт через `PATCH /api/contacts/:contactId` с `{ "favorite": true }` или `false`. `GET /api/contacts` возвращает сначала избранных, затем всех по имени, сортировка в SQL, и таблица следует этому порядку сразу после переключения, без перезагрузки.

Поиск: поле с подписью "Search" над таблицей. `GET /api/contacts?q=...` возвращает контакты, у которых имя или email содержит текст без учёта регистра, фильтрация в SQL; страница обращается к серверу по мере ввода и показывает "No matches", когда ничего не найдено.

Это должна быть настоящая фича с той же раскладкой по слоям, что у задач: контракт в `shared/contacts.ts`, таблица с миграцией и тремя контактами в сидах, один из них избранный, REST-маршруты под `/api/contacts` (список, получение, создание, обновление через PATCH, удаление), которые отвечают 400 на некорректные тела и 404 на неизвестные id, эндпоинты RTK Query и тесты с обеих сторон.
