Задачи копятся без всякой группировки. Нужны проекты, и каждая задача может принадлежать одному из них.

Проекты: пользователь открывает "Projects" из главной навигации и видит по адресу `/projects` таблицу с названием, описанием и колонкой "Tasks", где стоит число задач в проекте. Кнопка "New project" открывает `/projects/new`, форму с кнопкой "Create", после которой пользователь возвращается к списку. У проекта есть "Name" (`name`, обязательное, до 60 символов, сообщение "Name is required", уникально: повтор даёт 409 с `{ "message": "A project with this name already exists" }`) и "Description" (`description`, textarea, необязательное, до 300 символов, пустая строка если пусто).

Задачи получают `projectId`: id проекта или null. В форме задачи, и на странице создания, и на странице правки, появляется селект с подписью "Project", где по умолчанию выбрано "No project", а остальные варианты это проекты по названиям. В таблице задач появляется колонка "Project" с названием проекта или "—". В сидах два проекта; первые две задачи относятся к первому проекту, у третьей проекта нет.

API устроен так же по слоям, как у задач: контракт в `shared/projects.ts`, таблица с миграцией, REST-маршруты под `/api/projects` (список, получение, создание, обновление через PATCH, удаление), которые отвечают 400 на некорректные тела и 404 на неизвестные id. Каждый элемент `GET /api/projects` содержит `taskCount`, посчитанный в SQL, а не загрузкой всех задач. `POST` и `PATCH /api/tasks` отвечают 400 с `{ "message": "Unknown project" }` на несуществующий `projectId`. Проект, в котором ещё есть задачи, удалить нельзя: 409 с `{ "message": "Project still has tasks" }`.

Числа на странице проектов должны быть верными после создания задачи, её переноса в другой проект и удаления, без перезагрузки страницы. Обнови существующие тесты там, где этого требует изменение, и покрой новое поведение с обеих сторон.
