### Измеримые различия версий

Библиотеки, где базовые модели тянут старый API. Ровно тот эффект, который файнтюн должен показать на бенчмарке.

| Библиотека | Что поменялось | Что пишет базовая модель |
|---|---|---|
| Zod 4 | `z.email()` вместо `z.string().email()`, новая система ошибок | Zod 3 |
| Tailwind 4 | Конфиг через CSS и `@theme`, без `tailwind.config.js` | Tailwind 3 |
| shadcn 2026 | Импорты из единого `radix-ui`, без `forwardRef`, атрибут `data-slot` | `@radix-ui/react-*` и `forwardRef` |
| React 19 | `ref` как обычный проп, без `forwardRef` | `forwardRef` |
| React Router 8 | Импорт из `react-router` и `react-router/dom`, `react-router-dom` удалён | v6 |
| RTK 2 | Новые сигнатуры, `combineSlices` | RTK 1 |
| MSW 2 | `http.get` и `HttpResponse` вместо `rest.get` и `res(ctx.json())` | MSW 1 |

## Известные проблемы стека

1. **Лицензия на выход модели-учителя.** Решено: эксперимент частный, модель не распространяется. Если планы изменятся, датасет пересобирать открытой моделью.
2. **Учитель тоже не знает новых версий.** Срез знаний Claude раньше, чем TypeScript 6/7, React Router 8, Vite 8, MUI 9, ESLint 10. При генерации давать документацию в контексте; верификация через tsc это единственный фильтр мусора, а не дополнение.
3. **Библиотека компонентов слишком большая.** Нужен белый список из 20–30 компонентов для CRUD-приложений. Всё вне списка модель знает хуже, это принимаемое ограничение.
4. **Компоненты плохо тестируются в jsdom.** Radix требует полифиллов ResizeObserver, PointerEvent, scrollIntoView, DOMRect; Select и Dialog рендерятся в порталы. Одноразовая настройка в шаблоне, но тесты бенчмарка должны быть устойчивыми, иначе измеряем хрупкость тестов, а не модель.
7. **Шумные классы Tailwind.** Модели непоследовательно стилизуют: разные отступы и цвета на одинаковых элементах. Шаблон задаёт дизайн-токены через `@theme`, датасет использует только их. Это одна из вещей, которую файнтюн должен исправить измеримо.
5. **У каждой связки несколько правильных способов.** RHF через `register` или `Controller`, роутер через `createBrowserRouter` или `<Routes>`, тест RTK Query с реальным стором или с моком. Модель учится одному способу. Шаблон содержит эталон каждого паттерна, датасет генерируется от него. Список канонических паттернов это отдельный документ.
6. **Длина примеров.** Задача с контекстом из 3–4 файлов шаблона это 4–8 тысяч токенов. LoRA на 24 ГБ такое тянет, 16k уже впритык. Решить, сколько контекста класть в обучающий пример.

## Открытые вопросы

- [ ] Белый список компонентов shadcn (из ~50 выбрать ~20 для CRUD-приложений).
- [ ] Список канонических паттернов для каждой связки (отдельный документ `06-patterns.md`).
- [ ] Базовая модель: ручной прогон Qwen3.5-9B против Gemma 4 12B на 10 задачах (шаг 2). Нужен шаблон проекта хотя бы в черновом виде.
- [ ] Thinking-режим Qwen3.5: учить и запускать без thinking ради скорости или генерировать короткие reasoning-трассы учителем (Unsloth советует не меньше 75% reasoning-примеров для сохранения способности рассуждать).
- [ ] Инструмент для кодинга: Continue, Cline, Roo Code, aider, OpenCode или другой (шаг 3).
- [ ] Формат обучающих примеров: целые файлы, диффы или tool calls. Зависит от инструмента. В старом скелете был выбран SEARCH/REPLACE как формат для моделей, которые не умеют считать строки.
- [ ] Сколько контекста шаблона класть в обучающий пример.
- [ ] Какой общий бенчмарк использовать для проверки регрессии.
- [ ] Нужны ли агентские траектории в датасете или ограничиваемся одношаговой генерацией в первой итерации.
- [ ] Прогонять ли бенчмарк на 1.5B / 7B / 14B / 32B, чтобы понять, сколько даёт размер (идея из старого roadmap).
