| Библиотека | Что поменялось | Что пишет базовая модель |

## Известные проблемы стека

1. **Лицензия на выход модели-учителя.** Решено: эксперимент частный, модель не распространяется. Если планы изменятся, датасет пересобирать открытой моделью.
2. **Учитель тоже не знает новых версий.** Срез знаний Claude раньше, чем TypeScript 6/7, React Router 8, Vite 8, MUI 9, ESLint 10. При генерации давать документацию в контексте; верификация через tsc это единственный фильтр мусора, а не дополнение.
3. **Библиотека компонентов слишком большая.** Нужен белый список из 20–30 компонентов для CRUD-приложений. Всё вне списка модель знает хуже, это принимаемое ограничение.
4. **Компоненты плохо тестируются в jsdom.** Решено в шаблоне: полифиллы в `src/test/polyfills.ts`, тесты формы с Radix Select и диалога удаления проходят. Тесты бенчмарка всё равно должны быть устойчивыми, иначе измеряем хрупкость тестов, а не модель.
7. **Шумные классы Tailwind.** Модели непоследовательно стилизуют: разные отступы и цвета на одинаковых элементах. Шаблон задаёт дизайн-токены через `@theme`, датасет использует только их. Это одна из вещей, которую файнтюн должен исправить измеримо.
5. **У каждой связки несколько правильных способов.** RHF через `register` или `Controller`, роутер через `createBrowserRouter` или `<Routes>`, тест RTK Query с реальным стором или с моком. Модель учится одному способу. Шаблон содержит эталон каждого паттерна, датасет генерируется от него. Список канонических паттернов это отдельный документ.
6. **Длина примеров.** Задача с контекстом из 3–4 файлов шаблона это 4–8 тысяч токенов. LoRA на 24 ГБ такое тянет, 16k уже впритык. Решить, сколько контекста класть в обучающий пример.
