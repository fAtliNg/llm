# План реализации

Порядок шагов важен: бенчмарк и выбор инструмента идут до датасета, замер базовой модели идёт до обучения.

## Шаги

### 1. Стек и версии

Зафиксировать список библиотек с точными версиями. Ориентир: React, TypeScript, RTK Query, библиотека компонентов, библиотека форм, библиотека тестирования. Полный список в `04-decisions.md`.

Критерии выбора:

- Библиотеки с заметными различиями между версиями, чтобы эффект «модель знает версию X, а не Y» был измерим.
- Не больше 4–5 библиотек помимо React и TypeScript. Каждая библиотека умножает объём датасета, нужный для покрытия.

### 2. Базовая модель

Закрыт: Qwen3.5-9B. Сравнение кандидатов и особенности дообучения в `06-model.md`. Gemma 4 12B остаётся запасным вариантом на случай провального замера базы.

Учитывать: наличие GQA (компактный KV-кэш), поддержку tool calling, лицензию, наличие готовых рецептов в Unsloth.

### 3. Инструмент для написания кода

Закрыт: Pi. Обзор кандидатов и формат данных в `07-tool.md`. Схема четырёх инструментов `read`, `write`, `edit`, `bash` с native tool calls.

Почему до датасета: формат обучающих примеров должен совпадать с тем, как инструмент реально запрашивает модель. Иначе эффект от файнтюна частично теряется.

### 4. Шаблон проекта

Закрыт: `template/`. Скелет на выбранном стеке с эталонной фичей `tasks`, `npm run verify` проходит (typecheck, lint, format, 7 тестов). Паттерны описаны в `08-patterns.md`, конвенции для модели в `template/AGENTS.md`.

Используется трижды: основа для генерации данных, среда для бенчмарка, среда для работы пользователя.

### 5. Бенчмарк

Почти закрыт: прогон в `bench/` готов (validate, null, run с возобновлением, regrade, report с диагностикой), 34 задачи с эталонами в двух волнах, все проходят `validate` и проваливаются в `null`, reference на DeepSeek V4 Pro решает 32 из 34. Осталось: третья волна до 60–80 задач до финального сравнения. Детали в `09-benchmark.md`.

50–150 задач с тестами внутри шаблона плюс скрипт, который гоняет модель и считает метрики.

Метрики:

- Доля задач, проходящих тесты (pass@1).
- Доля компилирующихся решений (tsc без ошибок).
- Доля проходящих eslint.
- Частота использования несуществующих API.

Категории задач: компонент, слайс RTK Query, форма, тест на готовый компонент, правка существующего кода.

Бенчмарк это отложенная выборка. Задачи бенчмарка не должны попадать в обучающий датасет.

### 6. Замер базовой модели

Сделано на сервере 2026-09-15: база с обвязкой 36 из 76 (47%) при лимите 10 минут. На Mac та же модель давала 8%: разница в таймаутах и стене контекста, а не в способности. Голая и thinking-конфигурации по нулям на первых 11 задачах. Reference DeepSeek 46 из 48.

Три конфигурации: голая база, база с промптом и документацией в контексте, база внутри выбранного инструмента. Смотрим, где именно она проваливается, чтобы сфокусировать датасет.

### 7. Датасет

Начат: дизайн в `12-dataset.md`, захвачен точный запрос ученика, конвертер траекторий готов. Учитель DeepSeek через тот же Pi на пуле задач вне бенчмарка, в датасет идут только прогоны с зелёным verify. Следующее: генератор пула задач.

Самый долгий шаг.

Подход: синтетика от сильной модели, привязанная к реальному коду репозиториев на нужном стеке. Каждый пример прогоняется через tsc, eslint и тесты. Остаются только прошедшие.

Ориентир по объёму: 2–10 тысяч верифицированных примеров.

Формат примеров совпадает с форматом запросов инструмента из шага 3.

### 8. Обучение

Сделано: v1 (с дефектом формата) и v1.1 обучены 2026-09-15 на RTX PRO 6000, по часу и около 700 ₽ каждая. Подробности и уроки в `13-training.md`.

### 9. Упаковка

Merge LoRA в базу, конвертация в GGUF через llama.cpp, квантизация в Q4_K_M и Q8_0, MLX-версия для Mac, Modelfile для Ollama.

### 10. Финальное сравнение

Первое сравнение на сервере 2026-09-15: на 20 общих задачах ничья, v1.1 стабильнее по форме траектории. Следующее: Mac с лимитом 15 минут и повторения. Бенчмарк гоняется на итоговом Q4 GGUF, а не только на bf16.

Плюс проверка регрессии на общем бенчмарке (HumanEval или аналог), что общие способности не сломались.

## Оценка трудоёмкости

| Шаги | Ориентир |
|------|----------|
| 1–4 | неделя суммарно |
| 5 | неделя |
| 6 | пара дней |
| 7 | две-три недели |
| 8–10 | по несколько дней каждый |

Датасет и бенчмарк это две трети всей работы. Само обучение по сравнению с ними мелочь.
